# Test 0035: native bounded quotient walk

## Question

Can the native coordinate backend perform a multi-vertex bounded quotient
walk, constructing every destination block lazily, while reproducing GAP's
stable orbit membership and weighted stopping rule exactly?

## Inputs and provenance

- 4A pair checkpoint SHA-256
  `add26b95401d74fbaf29167782667080275d848b8cddabceecef40c2051c75c4`;
- source block 1,633,430, historical GAP twist 1;
- stable native source vertex `(1633430,1)` of weight 11;
- weighted class limit 250;
- GAP 4.12.1 and a C++20 build with warnings treated as errors.

The fixture is regenerated by GAP from the pair checkpoint. GAP translates
each historical twist ID to the native convention by taking the least key-v2
relative index in each beta12 orbit, then sorting those minima. The C++ walk
receives only the compact global coordinate checkpoint and the stable source
vertex.

## Method

C++ now materializes all relative representatives in one stable pair-twist
vertex, retains its first-coordinate transporter, applies beta13 and beta14,
and constructs each previously unseen destination block's relative double
cosets and pair-twist refinement on demand. Neighbors are deduplicated and
sorted by `(block, native_twist_id)`. The breadth-first walk uses the same
weighted overflow rule as GAP: a newly discovered vertex is retained, and the
walk stops once its cumulative inner-class weight exceeds the limit.

At this test's revision, the identity-product block still used GAP's separate
canonical-inner-tuple coordinate path and the first native walk rejected it.
Test 0037 subsequently adds a stable native identity coordinate and exercises
it in the complete known 5A component.

## Result

Both implementations checked two vertices before overflowing. They discovered
the same 25 stable quotient vertices, in the same order, with total inner-class
weight 256. The comparison includes every vertex ID and weight, not merely the
aggregate counts.

Reproduce the result with:

```bash
make check-native-kernel
```

## Verdict

Passed the first end-to-end native bounded-walk gate. This is a differential
correctness result, not yet a sustained throughput measurement or a native
production ledger.
