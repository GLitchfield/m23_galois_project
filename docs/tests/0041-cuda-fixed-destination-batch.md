# Test 0041: CUDA fixed-destination batch

## Question

Can the RTX 4080 advance beyond raw braid images by transporting each image
back to the fixed-first coordinate convention and returning only the last
three permutations of its destination key?

## Inputs and provenance

- implementation: the commit containing this note;
- fixture: `data/reference/native_kernel_fixture.tsv`, generated by GAP;
- NVIDIA GeForce RTX 4080, 16,376 MiB, compute capability 8.9;
- CUDA 12.0.140 with GCC 12.4 host compiler;
- input row: four packed degree-23 permutations plus one first-entry
  transporter, 115 bytes;
- output: two fixed-first destinations of three permutations each, 69 bytes
  per destination;
- benchmark batch: 1,000,000 alternating fixture rows.

With a compatible local CUDA toolchain, reproduce with:

```bash
scripts/benchmark-cuda-permutation-batch.sh 1000000
```

## Exact result

The CPU and GPU implementations agree bit-for-bit on every returned
destination. The host braid formulas continue to agree with the independent
GAP fixtures. A one-million-row run measured:

- CPU single core: 5.250 million destination attempts/second;
- GPU kernel: 25.502 million attempts/second;
- GPU including input and output transfers: 16.272 million attempts/second;
- transfer/kernel split: 22.491 ms host-to-device, 78.425 ms kernel, and
  21.995 ms device-to-host.

This is about 3.1 times one CPU core including transfers. Because the GPU is an
additional resource, the relevant comparison would be combined CPU+GPU
verified throughput, not whether this stage alone beats the whole CPU search.

## Limits and verdict

Passed the fixed-first transport and packed destination-key gate. This is a
materially stronger stage than test 0039's raw braid-image microbenchmark, and
its lower throughput is expected because it performs inverse, composition,
conjugation, and a larger input transfer.

The sample still alternates only two GAP fixtures. It does not yet resolve the
three returned permutations to stable block/twist IDs, sort or deduplicate
keys, union connected components, or commit certificates. This was the last
GPU experiment; the kernel was not integrated into a ledger.
